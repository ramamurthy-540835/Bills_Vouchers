# Automatic customer setup — 16 October 2026

Business profile now contains Add customer profile. An authenticated client/accountant/administrator can enter a legal name and optional GSTIN/website, create a separate workspace and continue to onboarding for contacts, address, registration details and logo. Viewers cannot create customers. Creation grants ownership only to the authenticated creator; it does not grant platform administrator access or match existing tenants by GSTIN. Invite additional people separately through Workspace access.

POST /api/settings/customers creates clients, client_memberships, client_user_role, gst_client_profile and profile_audit records in one guarded BigQuery transaction, using existing schemas including migration 016. No new migration is required. The selected session switches only after setup succeeds. The standard customer selector subsequently lists the new membership.

GCS uses the existing private aidirac-503309-bills-voucher-documents bucket. A create-only {client_id}/profile/workspace.json marker reserves the customer path before the SQL transaction; existing invoice/logo writers already use that tenant prefix. The marker contains only an internal identifier and version, not company personal information. No per-customer bucket, dataset or GCP IAM principal is created. Shared storage remains protected through backend tenant membership, uniform bucket-level access and public access prevention.

The frontend retains a request UUID in sessionStorage until success. The backend derives a stable customer UUID from the authenticated user and request UUID. Retries reuse the storage marker and do not insert duplicate customer records. SQL validates retained ownership on retries. If GCS fails, SQL is not attempted; if SQL fails, the nonpersonal marker may remain for retry. Historical objects are not purged automatically. A new deliberate setup after success creates a distinct workspace; it does not merge tenants with matching names or GSTINs.
